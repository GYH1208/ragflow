# WorkBuddy 知识库图片下载

`get_chunk_image` 返回原生图片，并在来源信息中附带短期下载链接。
服务端不返回用户电脑上的文件路径；由 WorkBuddy 下载到明确的工作区路径，
再展示附件。这样不依赖客户端的缓存目录结构。

## 部署顺序

1. 发布包含此变更的 MCP 服务代码，重启该 MCP 进程。
2. 确认 `RAGFLOW_MCP_PUBLIC_URL` 是 WorkBuddy 可访问的完整 MCP 地址。
   反向代理需转发该地址下的 `/image-download/*` 路径到同一个进程；
   若已有目录导出下载配置，可按相同方式配置图片路由。
3. 在 WorkBuddy 刷新/重连 MCP 工具，并更新下面的 Skill 规则。
4. 取一张尚未下载过的图片，核对字节、哈希、附件展示与各阶段耗时。

不需要重跑文档解析或重启 RAGFlow 后端。链接15分钟后过期，MCP重启也会使
已有链接失效。链接本身授予该图片快照的下载权限，不应公开分享。

## 替换 WorkBuddy Skill 的取图规则

将下面规则写入电脑上的 `ragflow-kb-unified/SKILL.md`，并同步清理引用文档和
长期记忆中冲突的旧规则。此仓库不能直接修改用户 Windows 上的 Skill。

```text
知识库图片交付流程：
1. 使用与正文检索相同的企业 MCP 连接器和当前用户身份。
   已获得有效 dataset_id、document_id、chunk_id 且 image_id 非空时，
   直接调用 get_chunk_image；缺少图片分块信息时才读取 get_document_chunks。
   chunk_id 使用分块的 id，不使用 image_id。
2. 优先读取工具结果中的 download_url、filename、mime_type、size_bytes、
   sha256、expires_at。使用客户端的下载工具或程序，将该 URL 的响应以
   二进制保存到明确的工作区路径。沿用 filename 的扩展名；不要覆盖无关文件。
   下载只使用返回的短期链接，不附带企业票据、API Key 或其他登录凭证。
3. 检查下载成功、实际字节数和 SHA-256 与工具结果一致，再调用 present_files，
   传入实际存在的本地路径，并标注案例/文档来源。显示成功后才说附件已交付。
4. 若没有下载工具，提供返回的下载链接供用户使用，说明有效期。
   如链接过期或进程重启导致404，可再次调用同一企业连接器获取新链接，
   最多重试一次；持续失败就报告具体错误。
5. download_error 表示文件下载入口不可用，不等于图片或知识库无权限。
   保留可用的原生图片展示，并说明具体限制。收到真正的权限拒绝时如实报告。
6. 禁止扫描整个用户目录、.workbuddy、临时目录寻找缓存图片；
   禁止 find + stat + sort 全量排序；禁止模型手工重构 Base64；
   禁止把远程 URL 当本地文件路径，禁止因旧手工 Key 失败就认定企业连接器无权限。
7. 单纯取图时，先交付附件和简短来源；仅在用户要求时进一步分析或裁剪。
```

删除旧的“用户交付必须走手工 Key 脚本”“产品缺陷库无取图权限”及
“图片不会自动缓存”等绝对规则。原生图是否缓存、是否能内联显示取决于客户端，
此次文件交付不依赖这些实现细节。

## 验收

用 DX-R059 的图片与另一张从未取过的图片分别检查：

- 实际调用的是企业连接器 `get_chunk_image`；返回下载元数据和原生图片。
- 下载文件的大小和 SHA-256 与元数据一致，附件能打开且来源正确。
- 不调用全目录搜索，也不重新进行无必要的文档查找。
- 分别记录 MCP 调用、文件下载、校验/展示、整轮耗时。
- 正常下载不需要额外登录凭证；过期链接明确失败，重新取链接后可恢复。

服务端接口测试不能代替 WorkBuddy 桌面端验收，也不能保证固定的整轮耗时。
如仍然缓慢，应按工具调用时间拆解，区分网关、下载和模型处理时间。
