# MCP 调用分析看板接入方案

## 目标与范围

在现有 `/chat-analytics` 页面中加入 WorkBuddy 员工 MCP（9396）调用看板，供真实使用情况汇报。沿用现有 React、React Query、Recharts 和 Quart API，不创建独立站点。

## 方案比较

1. **累计看板（用户已选择）**：读取已有持久化计数，展示总量、分类和接口排行。可以完整展示现有数据，改动范围小。
2. **累计看板加历史采集**：额外保存每天的计数变化，随后展示每日趋势。现有计数没有历史时间信息，过去日期无法回填，需单独定义采集和重置处理。

不把 MCP 调用次数直接加入聊天提问次数：一次问题可能触发多次工具调用。

## 推荐页面设计

- 在页面标题下增加「聊天问答」「MCP 调用」页签，保留原聊天分析布局与筛选。
- MCP 页签展示累计调用总数、知识检索调用数、文档内容读取调用数、目录与图片等其他调用数四张卡。
- 用横向条形图展示各接口调用次数，由高到低排序；显示中文用途、接口名、次数和占比。
- 显示数据保存时间，提供刷新按钮，并每 30 秒刷新一次。后端计数本身最多有约 10 秒的持久化延迟。
- 全零时显示明确空状态；读取失败时显示加载失败及重试，不能把文件缺失或损坏当作零调用。
- 适配现有明暗主题和窄屏布局。

## 数据口径

数据源为 `logs/mcp-tool-counts-9396.json`，后端部署可配置路径。只能由服务器配置选择文件，不允许请求参数指定文件路径。

- 累计总数：文件中所有合法工具计数之和。
- 知识检索：`ragflow_retrieval` 与 `search_documents`。
- 文档内容读取：`get_document_chunks`。
- 其他调用：图片、目录浏览、文档列表、目录导出，以及未来新增工具，确保分类之和等于总量。
- 所有接口分别展示，新增未知工具保留原名并归入其他调用。
- 统计从计数功能启用后累计，包含进入执行后失败的调用，不含初始化、工具发现和执行前被拒绝的请求。
- 不提供今日、近 30 天、成功率、用户数或历史趋势，因为现有数据不支持。
- 保留所有真实计数，仅提供读取接口。

## API 与访问边界

新增独立的登录保护 MCP 统计 API，使聊天分析与 MCP 数据加载和失败状态相互独立。

当前文件是整个服务的汇总，不是按租户的统计。默认仅向超级管理员提供该看板数据；普通账号在 MCP 页签看到权限提示，聊天分析保持可用，避免把服务总量误作为普通账号所属租户的数据。具体实现复用当前项目的超级管理员身份字段。

API 返回有效状态、累计总量、分类总量、工具列表及保存时间；文件异常返回不可用状态，响应不暴露服务器路径或底层异常。

## 验证与交付

- 后端验证：总量与分类相符、未知工具、全零、缺失/损坏/负数/布尔值数据、未登录/非超级管理员访问。
- 前端验证：原聊天统计保留、页签切换、MCP 图表与数字、刷新、空数据与错误状态，以及窄屏布局。
- 页面部署前核对生产计数未被更改；通过现有 9222 前端和 9380 后端服务提供看板。
