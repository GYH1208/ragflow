# 聊天问答分析看板设计

## 目标

在 RAGFlow 中增加一个轻量的“问答分析”看板，让当前租户的用户查看所有聊天助手产生的问答次数。第一期只关注次数，不统计回答率、正确率、Token、响应耗时或分来源数据。

## 统计口径

- 一条 `role == "user"` 的聊天消息计为一次问答。
- 助手开场白、助手回答、系统消息和工具消息不计数。
- 合并统计 `Conversation` 和 `API4Conversation` 中归属于当前租户聊天助手的数据。这会覆盖站内聊天、分享页/API 以及写入 `Conversation` 的外部聊天渠道。
- 不展示各来源的拆分数据，只展示合并后的总次数。
- 消息存在有效 `created_at` 时，该时间用于趋势归档；历史消息缺少该字段时，使用会话的 `update_time`，再回退到 `create_time`。
- 本期不新增统计事件表，因此缺少单轮时间的历史数据只能按会话时间近似归档；累计次数仍按实际用户消息数计算。

## 页面设计

新增顶层路由 `/chat-analytics` 和导航入口“问答分析”。页面沿用 RAGFlow 现有的颜色、字体、卡片、按钮、日期选择器和表格组件，不引入新的视觉依赖。

页面从上到下包含：

1. 三张概览卡：累计问答次数、近 30 天问答次数、今日问答次数。
2. 一张问答次数趋势折线图，支持按天、按周和按月聚合。
3. 筛选栏：聊天助手和时间范围。默认选择全部助手和近 30 天。概览卡中的“累计”始终表示全历史，另两张卡和趋势图根据它们各自的固定或选定时间口径展示。
4. 明细表：仅展示“聊天助手名称”和“问答总次数”，默认按次数降序排列。时间筛选会同时影响趋势图和明细表。

页面需要具备加载、空数据和请求失败状态，并在常见桌面宽度下保持与参考截图相近的层级，小屏时卡片和筛选项可换行。

## 后端与数据流

新增一个受登录保护的租户级统计接口。接口接收可选的聊天助手 ID、开始日期、结束日期和聚合粒度，返回：

- `total_count`：当前聊天助手筛选下的全历史问答数。
- `last_30_days_count`：当前聊天助手筛选下的近 30 天问答数。
- `today_count`：当前聊天助手筛选下的今日问答数。
- `trend`：按请求粒度聚合的时间点与次数。没有问答的时间点补零。
- `assistants`：选定时间范围内各聊天助手的总次数。
- `assistant_options`：当前租户可见的全部聊天助手 ID 和名称，不受当前助手和日期筛选影响，仅用于筛选下拉选项。

服务先通过 `Dialog.tenant_id` 确定当前租户可见的聊天助手，再分批读取两类会话的消息 JSON 并在服务端完成计数。不向前端返回问题或回答原文。接口需校验日期范围和粒度，且不允许通过助手 ID 访问其他租户的数据。

## 前端结构

- 路由层增加“问答分析”路由并加入全局导航选中规则。
- 新增独立页面目录，将概览卡、趋势图、筛选栏和明细表拆分为小组件。
- 新增服务请求和 React Query hook，筛选变化时使用新查询参数刷新。
- 折线图复用项目已有的 Recharts 能力，样式调整为参考图中的蓝色折线与浅色网格。
- 中英文文案加入现有 i18n 资源，不在 JSX 中固定写死。

## 错误与边界情况

- 租户没有聊天助手或指定时间没有数据时，卡片显示 `0`，趋势图显示零值时间轴，表格显示空状态。
- 单个会话的 `message` 不是数组或包含异常项时，跳过异常项并继续统计，不让一条损坏数据导致整个看板失败。
- 日期参数非法、开始日晚于结束日或粒度非法时返回可读的参数错误。
- 统计请求失败时保留筛选条件并显示错误提示，用户可重试。

## 测试与验收

后端测试覆盖用户消息计数、开场白排除、两类会话合并、助手与日期筛选、日/周/月聚合、缺少消息时间的回退规则、损坏 JSON 容错和租户隔离。

前端测试覆盖路由可达、概览数据渲染、聚合粒度切换、助手/日期筛选刷新、空状态和错误状态。完成后在实际浏览器中与用户提供的参考截图对照，检查页面层级、间距、折线图、筛选交互和响应式表现。

## 非目标

第一期不包含回答正确率、回答率、未命中问题、用户排名、问题原文明细、来源拆分、数据导出、新统计事件表或定时汇总任务。
