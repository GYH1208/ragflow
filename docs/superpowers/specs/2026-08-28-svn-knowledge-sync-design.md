# SVN 体系文件知识库同步设计规格

## 背景

研发体系文件存放在只读 VisualSVN 仓库中。当前人工流程需要在本地通过 PowerShell/SVN 拉取路径、与文件表格比对、下载升版文件，再手动替换 RAGFlow 知识库文档。该流程耗时，且容易遗漏旧版删除、重新解析和目录层级。

服务器已经安装 Subversion 1.14.1，并已验证能以只读账号访问 VisualSVN。RAGFlow 已具备连接器调度、知识库分层文件、相对路径上传和文档解析能力，因此本功能在 RAGFlow 侧实现，不修改 VisualSVN 服务端。

## 目标

1. 增加原生 SVN 数据源连接器，通过只读账号读取已提交版本。
2. 每 60 分钟自动同步，并提供不会预删文档的手动“立即同步”能力。
3. 只同步以下四个 SVN 子树：
   - `1、一级文件`
   - `2、二级文件`
   - `3、三级文件`
   - `4、四级文件`
4. 完整保留四个同步根目录及其有效子目录的相对层级。
5. 任何目录片段或文件名包含“旧版”时，排除该项；目录命中时排除整棵子树。
6. 每个目录优先选择全部 `.doc`/`.docx` 文件；只有该目录不存在 Word 文件时才选择其中的 `.pdf` 文件。
7. 只下载新增或内容指纹变化的文件；变化后必须删除旧分块并重新解析。
8. SVN 文件删除、移动或升版后，连续两次完整且成功的快照均确认缺失，才从 RAGFlow 删除旧文档。
9. 删除旧文档后，只清理连接器创建且已经为空的目录，不删除知识库根目录或用户创建/复用的目录。

## 非目标

- 不在 VisualSVN 服务器安装插件、Hook 或新增接口。
- 不向 SVN 执行 `commit`、`delete`、`move`、`mkdir` 等写操作。
- 不同步 `00_体系文件` 下除四个指定子树之外的文件。
- 不同步纯空目录；只创建通向有效知识文档的目录链。
- 不根据文件名中的版本号判断新旧；以当前已提交树和稳定相对路径为准。
- 不把 PDF 与同目录中的 Word 副本同时写入知识库。

## 兼容性边界

本功能会复用连接器编排、知识库文件夹和解析任务等共享模块，但新增参数必须全部是可选参数，并保持现有默认值：

- 非 SVN 连接器不提供 `relative_path`，继续保持当前上传行为；
- 普通本地上传和非 SVN 连接器不提供 `content_version`，解析任务 digest 与当前版本完全一致；
- 通用删除服务的 `confirmation_scans` 默认仍为 `1`，只有 SVN 调用时显式传入 `2`；
- 受管目录记录与空目录清理只在 `source_type` 以 `svn/` 开头时启用；
- `Connector2Kb.sync_state` 是带空对象默认值的新增字段，现有连接器关系不读取也不写入其中的 SVN 状态；
- 现有“重建”、本地上传、文件夹上传、解析、检索和其他数据源的接口响应保持不变。

因此，本功能允许修改共享函数的签名以传递可选上下文，但不允许改变任何非 SVN 调用路径的可观察行为。相关回归测试必须在交付前通过。

## 配置模型

SVN 连接器配置使用以下字段：

```json
{
  "repository_url": "https://svn.example.test/svn/company",
  "base_path": "00_公用文件/00_体系文件",
  "include_roots": [
    "1、一级文件",
    "2、二级文件",
    "3、三级文件",
    "4、四级文件"
  ],
  "exclude_name_contains": ["旧版"],
  "credentials": {
    "username": "",
    "password": ""
  },
  "sync_deleted_files": true,
  "batch_size": 8
}
```

连接器默认 `refresh_freq=60`、`prune_freq=60`。前端把密码字段渲染为 Password，不在同步日志、异常消息或命令行参数中输出密码。

## SVN 读取与快照一致性

每次同步先对仓库 URL 执行只读 `svn info --xml`，获得仓库 UUID 和当前 revision。随后四个根目录的 `svn list --xml --recursive -r <revision>`、文件下载 `svn cat -r <revision>` 必须全部固定到同一 revision，避免扫描过程中 SVN 又产生提交而形成混合快照。

SVN 命令必须：

- 通过参数数组调用，不拼接 shell 字符串；
- 使用 `--non-interactive --no-auth-cache --password-from-stdin`；
- 仅通过标准输入传入密码；
- 设置超时并限制错误信息，不回显凭据；
- 校验 URL 仅使用 `https`；
- 对 XML 输出进行结构化解析；
- 在任意根目录扫描失败时把整次快照标记为失败，不执行缺失计数或删除。

证书信任继续使用服务器当前 Subversion 配置中已经永久接受的证书指纹。连接测试应校验仓库 UUID、只读访问和四个根路径可列出。

## 文件选择规则

连接器将四次列表结果规范化为相对于 `base_path` 的 POSIX 路径。处理顺序如下：

1. 拒绝绝对路径、`.`、`..`、NUL、反斜杠和越出配置根目录的路径；
2. 任一路径片段包含排除词时跳过；
3. 仅保留扩展名大小写不敏感匹配 `.doc`、`.docx`、`.pdf` 的普通文件；
4. 按父目录分组；
5. 若组内有 `.doc`/`.docx`，选择该组全部 Word 文件并忽略 PDF；否则选择该组全部 PDF；
6. 结果按 UTF-8 路径稳定排序。

文档稳定键为 `<repository_uuid>:<relative_path>`。指纹为 `xxhash128(repository_uuid, relative_path, last_changed_revision, size)`。路径不变且指纹不变时不下载；路径改变视为新增路径，旧路径进入两次缺失确认流程。

## RAGFlow 目录映射

连接器产出的 `Document` 增加可选 `relative_path` 字段，例如：

```text
1、一级文件/BDQM-01_V4.1_质量手册打印/BDQM-01_V4.1_质量手册打印.docx
```

同步编排层把该路径逐文档传给 `FileService.upload_document(relative_paths=...)`。现有文件服务负责校验 Unicode 相对路径、逐级创建或复用知识库文件夹、在目标父目录内处理重名，并把 `Document.location` 写为相对路径。

文件夹创建时，只有本次真正新建的文件夹 ID 才记录为该 `connector_id + kb_id` 的受管目录。复用知识库中已存在的同名目录时，不把它标记为受管目录。

## 更新与重新解析

同一路径的 SVN 文件发生内容变化时沿用稳定文档 ID：

1. 覆盖知识库存储对象并更新 `Document.content_hash`；
2. SVN 调用解析时显式把内容指纹作为可选 `content_version` 纳入任务 digest；其他上传和连接器不传该参数；
3. 旧 digest 与新 digest 不同，因此旧分块不能复用；
4. 删除旧任务和旧分块，提交新解析任务；
5. 新解析成功后，检索结果只来自当前 SVN 内容。

内容未变化时连接器不下载、不上传、不创建解析任务。

## 两次缺失确认与目录清理

每个 `Connector2Kb` 关系保存轻量同步状态：

```json
{
  "missing_counts": {"<document_id>": 1},
  "managed_folder_ids": ["<folder_id>"],
  "last_successful_revision": 72089
}
```

只有四个根目录全部成功列出并完成选择后，才更新状态：

- 当前快照存在的文档从 `missing_counts` 移除；
- 第一次缺失记为 `1`，保留 RAGFlow 文档；
- 下一次完整成功快照仍缺失时变为 `2`，删除文档；
- 扫描失败、认证失败、超时或 XML 无效时不增加计数；
- 删除失败时保留计数，下一次重试；
- 删除成功后，从叶子向上检查 `managed_folder_ids`，仅删除空的受管目录，并在知识库根目录处停止。

## 调度与手动同步

沿用 RAGFlow 连接器轮询调度：

- `refresh_freq=60`：每小时执行增量同步；
- `prune_freq=60`：每小时执行完整快照和两次缺失确认；
- 新建连接器并关联知识库后立即调度首次全量同步；
- 编辑连接器并保存时重新调度；
- 新增“立即同步”操作：立即调度一次 SYNC 和一次 PRUNE，但不预先删除任何文档；
- 现有“重建”操作继续保留为显式破坏性全量重建，不能作为日常同步入口，界面必须区分两者。

## 验收条件

1. 四个根目录各至少一份有效文件可同步，并在 RAGFlow 中看到相同目录层级。
2. 任意层级名称含“旧版”的目录和文件均不出现在知识库。
3. 同目录同时有 DOCX 和 PDF 时只同步 DOCX；删除 DOCX 后，PDF 在下一次同步成为新增候选。
4. SVN 文件内容变化后只下载该文件，并产生新的解析分块。
5. SVN 文件第一次缺失后 RAGFlow 仍保留；第二次完整成功快照仍缺失后删除。
6. 第一次缺失与第二次扫描之间若发生认证/网络失败，旧文档不得删除。
7. 移动文件后新路径被创建；旧路径满足两次确认后删除；只剩空目录时仅清理受管目录。
8. 运行日志中不出现 SVN 密码，SVN 仓库无任何写操作。
