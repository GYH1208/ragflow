# 图片证据冷启动与现行版本检索修复设计

## 背景

2026-07-31 对“研发”助手执行了 10 个真实后端回归案例。引用下标与来源文件聚合保持一致，精确文件编号和无证据兜底也符合预期，但暴露了两个独立问题：

1. 图片证据 reranker 在进程冷启动后的首次调用耗时约 902 ms，超过当前 900 ms 的硬截止时间，因此文字回答和引用正确，但图片以 `rerank_timeout` 失败关闭；同一案例后续两次分别约 477 ms 和 415 ms，均选中正确图片。
2. 多轮问题询问“现行软件确认报告模板”时，检索结果同时包含现行目录和“旧版”目录。回答虽然正确指出 V1.2，但为了对比历史版本又引用了 V1.0、V1.1，造成来源文件数量超出当前问题的必要范围。

本设计在不改变图片候选定义、不降低失败关闭标准、不影响历史版本查询的前提下修复这两个问题。

## 目标

- 冷启动时为图片证据 reranker 提供足够的完成预算，避免已验证正确的图片因 900 ms 边界抖动而不发送。
- 当用户明确询问现行、当前、最新或有效版本，或明确要求不要旧版时，旧版目录中的 chunk 不参与本轮回答和引用生成。
- 保持文字回答优先发送；图片证据失败不撤回、不延迟文字回答。
- 保持图片引擎只处理带 `image_id` 的 chunk，普通文本 chunk 不成为图片候选。
- 保持历史版本、版本差异和旧版追溯问题能够检索旧版资料。

## 非目标

- 不修改图片 reranker 的最低分数、分差、候选短名单大小或最多发送两张图片的规则。
- 不给图片证据解析增加自动重试。
- 不改变企业微信图片上传与发送协议。
- 不自动推断所有文件家族的最高版本，也不修改知识库文档状态或元数据。
- 不默认对所有问题永久隐藏旧版；过滤只由明确的当前版本意图触发。

## 设计决策

### 1. 图片证据预算调整为 1.5 秒

将 `EvidenceConfig.timeout_seconds` 的默认值由 `0.9` 调整为 `1.5`。

证据解析仍在文字发送成功之后执行，因此该调整不会增加文字首包或完整文字回答的等待时间；最坏情况下只会让后续图片比现在多等待约 0.6 秒。超过 1.5 秒仍返回 `rerank_timeout` 并且不发送未经确认的图片。

本次不采用超时后重试。同步 reranker 线程在协程超时后不能被安全停止，现有租约会等待真实线程结束后再释放容量和关闭模型。立即重试可能占用第二个工作线程，增加 `rerank_busy` 和执行器饱和风险。

显式传入较小 `EvidenceConfig(timeout_seconds=...)` 的测试和调用方保持原有语义，不受默认值变化影响。

### 2. 识别明确的当前版本意图

在聊天检索服务中增加纯函数，用于判断最终检索问题是否明确要求当前有效资料。初始支持以下中文意图：

- `现行`
- `当前`
- `最新`
- `有效版本`、`有效的版本`
- `不要旧版`、`不引用旧版`、`排除旧版`

判断对象是经过多轮改写和跨语言处理后的 `generation_question`。这样启用 `refine_multiturn` 时，“那现行报告呢？”改写出的独立问题也能触发同一规则。

本轮只处理中文研发知识库的已知表达，不扩展模糊词语如“新版”“推荐版本”，避免把普通业务语义误判为文档版本过滤。

### 3. 过滤旧版目录 chunk

当且仅当检测到当前版本意图时，在主检索、目录增强和子 chunk 展开完成后，对 `kbinfos["chunks"]` 执行旧版过滤，然后再进入 `kb_prompt()`、回答生成和引用处理。

旧版判断基于 chunk 的文档路径字段：

- 优先读取 `docnm_kwd`；
- 兼容读取 `document_name`；
- 将反斜杠转换为正斜杠；
- 仅当规范化路径的某一段完整等于 `旧版` 时判定为旧版目录。

完整路径段判断可避免误伤文件名正文中偶然出现“旧版”两个字的正常文件。

过滤发生在回答提示构造之前，因此：

- 旧版内容不会进入本轮 LLM 知识上下文；
- LLM 无法为旧版 chunk 生成有效引用；
- `reference.chunks`、`doc_aggs` 和照片证据引擎都只会接触过滤后的候选；
- 若过滤后没有知识块，沿用现有无证据兜底，不调用回答模型。

`doc_aggs` 在这一阶段不是最终可信来源集合；最终仍由回答中的有效引用通过 `_build_cited_doc_aggs()` 重建。为避免中间统计继续包含旧版，过滤时同步删除只属于被过滤 chunk 的旧版聚合项，但不改变最终引用聚合的权威来源。

### 4. 历史查询保持原行为

以下问题不触发当前版本过滤：

- “V1.0 的模板内容是什么？”
- “比较 V1.0 和 V1.2 的差异。”
- “旧版软件确认报告有哪些章节？”

其中显式文件编号仍优先使用现有精确文件范围解析。只有问题同时明确要求当前版本时，才应用旧版目录过滤；例如“现行版本与旧版有什么差异”同时包含当前和历史意图，属于对比查询，不应过滤旧版。

为支持该例外，当前版本意图判断还需识别明确的历史对比表达，例如 `对比`、`比较`、`差异` 配合 `旧版` 或两个版本编号。存在这类表达时，不启用旧版过滤。

## 数据流

```text
用户消息
  → 多轮问题改写（可选）
  → generation_question
  → 精确文件编号范围（如有）
  → 混合检索 / rerank / TOC / 子 chunk
  → 检测当前版本意图
      ├─ 否：保留原候选
      └─ 是：过滤路径段为“旧版”的 chunk
  → kb_prompt
  → LLM 回答和引用规范化
  → reference.chunks / doc_aggs
  → 渠道文字发送成功
  → 若存在 image_id：图片证据 rerank（默认预算 1.5 秒）
  → 可信则发送图片，否则失败关闭
```

## 组件边界

### `rag/nlp/evidence.py`

只调整 `EvidenceConfig.timeout_seconds` 默认值。图片硬门禁、短名单、rerank 阈值和最多图片数保持不变。

### `api/db/services/dialog_service.py`

增加聚焦的纯函数：

- 判断是否为当前版本意图；
- 判断是否为历史对比意图；
- 判断 chunk 是否来自完整的“旧版”路径段；
- 按意图过滤检索结果并同步整理候选聚合。

异步检索主体只负责在 `kb_prompt()` 之前调用纯函数，不承担字符串细节。

### 照片证据链路

`api/channels/bootstrap.py`、`api/db/services/evidence_service.py` 和 `api/channels/wecom/channel.py` 不改变。它们继续在文字发送确认后、存在 `image_id` 时运行。

## 错误处理与可观测性

- 1.5 秒后仍超时：保持 `status=error`、`reason=rerank_timeout`，不发送图片。
- 过滤后无 chunk：返回现有配置的 `empty_response` 或系统默认无依据响应。
- chunk 缺少文档名：保留该 chunk，不因元数据缺失误删证据。
- 过滤日志只记录过滤前后数量和会话/追踪标识，不记录完整问题或文档内容。
- 增加 `current_version_filter_applied`、`before_chunk_count`、`after_chunk_count` 等结构化字段，便于复测。

## 测试策略

### 图片证据预算

- 默认配置断言从 0.9 秒更新为 1.5 秒。
- 显式 0.01 秒的超时测试继续证明失败关闭和租约延迟释放。
- reranker 异常、容量占满和模型不可用测试保持原结果。

### 当前版本意图

- “现行模板”“当前有效版本”“最新报告”“不要引用旧版”触发过滤。
- 普通问题和明确历史版本问题不触发过滤。
- “比较现行版本与旧版差异”不触发过滤。

### chunk 过滤

- `/旧版/` 和 `\\旧版\\` 路径被过滤。
- 文件名中包含“旧版说明”但没有完整路径段时不被过滤。
- 缺少文档名的 chunk 被保留。
- 最终提示、`reference.chunks` 和 `doc_aggs` 不包含被过滤旧版文档。
- 过滤后为空时返回无依据响应，不调用回答模型。

### 回归范围

- `test/unit_test/rag/test_evidence.py`
- `test/unit_test/api/db/services/test_evidence_service.py`
- `test/unit_test/api/db/services/test_dialog_service_final_answer.py`
- `test/unit_test/api/channels/test_bootstrap.py`
- `test/unit_test/api/channels/test_wecom_channel.py`

完成自动化测试后，复跑两个真实案例：

1. `BDOP-YF-098_V1.2 中角度尺寸标注对应哪个图？`，冷启动应在 1.5 秒内选择图 42；
2. 多轮从“软件确认方案”追问“那软件确认报告使用哪个现行模板？”，最终来源中不应出现“旧版”目录。

真实图片案例只执行证据解析和选图判断，不实际向企业微信发送测试图片。

## 验收标准

- 冷启动图片案例不再因约 902 ms 耗时触发默认超时，并选中预期图片。
- 图片处理超过 1.5 秒时仍失败关闭。
- 明确当前版本问题的最终知识上下文、引用 chunks 和来源文件中不存在完整“旧版”路径段。
- 历史版本及版本对比问题仍可检索旧版资料。
- 普通文本 chunk 仍不会成为图片候选。
- 相关单元测试和真实回归案例全部通过。
