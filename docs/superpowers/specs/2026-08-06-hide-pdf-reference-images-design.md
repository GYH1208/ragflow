# PDF 引用截图过滤设计

## 背景与目标

当前聊天回答的引用 Chunk 可能携带 `image_id`。这些图片既可能是问答文档中的业务配图，也可能是 PDF 解析后生成的页面裁剪截图。企业微信和网页聊天目前会把两类图片按相同方式展示或发送。

首版需要保留问答文档中的答案配图，同时禁止展示和发送所有 PDF 来源的引用截图。文字答案、引用标记、来源名称和知识检索行为保持不变。

## 已确认范围

- 在“聊天设置 → 高级设置”增加“展示 PDF 引用截图”开关。
- 开关默认关闭；关闭时，所有文件名以 `.pdf` 结尾的引用 Chunk 均不得携带可展示的图片标识。
- 非 PDF 文档中的引用图片继续按现有规则展示和发送。
- 规则同时作用于网页聊天、分享页面及企业微信等外部聊天渠道，避免同一助手在不同入口行为不一致。
- PDF 仍参与检索和回答生成；仅过滤其引用截图。
- 不新增知识库级或文件级策略，不识别“制度”关键词，也不修改文档解析和索引。
- 已经发送到企业微信的历史图片无法撤回。

## 方案比较

### 方案一：按 PDF 文件扩展名过滤（采用）

使用引用 Chunk 已有的 `document_name`/`docnm_kwd` 判断来源文件是否为 PDF。关闭开关时，只清空 PDF Chunk 的 `image_id`/`img_id`，保留 Chunk 本身及其文字、文档名称和文档 ID。

优点是无需数据库迁移、无需重新解析知识库，并能保留非 PDF 问答文档配图。文件扩展名也是当前引用数据中最直接、稳定的来源格式信息。

### 方案二：按 Chunk 的 `doc_type` 过滤（不采用）

`doc_type` 表示 Chunk 内容是文字、图片或表格，不代表来源文件格式。PDF 页面截图和问答文档配图都可能是图片类型，使用该字段会误删需要发送的问答配图。

### 方案三：知识库或文件级权限（后续可选）

为每个知识库或文件增加“允许展示引用图片”策略，能够处理部分 PDF 可展示、部分 PDF 不可展示的情况，但需要新增管理入口、持久化规则和更多权限校验。当前已确认所有 PDF 均不发送，因此首版不引入这层复杂度。

## 配置与界面

在助手的 `prompt_config` 中增加布尔字段：

```json
{
  "show_pdf_reference_images": false
}
```

前端将开关放在“高级设置”中的“显示引文”之后、“发送引用原文件”之前：

- 名称：展示 PDF 引用截图
- 提示：关闭后，PDF 来源的页面截图不会在聊天中展示，也不会发送到外部聊天渠道；非 PDF 文档配图不受影响。

默认关闭。读取缺少该字段的旧助手配置时也按关闭处理，以确保升级后立即执行已确认的 PDF 截图保护规则。管理员仍可按助手显式开启。

## 数据流

```text
检索得到引用 Chunk
  -> 生成文字回答和引用
  -> 读取助手 show_pdf_reference_images
  -> 开关关闭且 document_name 以 .pdf 结尾
       -> 保留引用 Chunk
       -> 清空 image_id / img_id
  -> 格式化并保存 reference
  -> 网页端只展示仍有 image_id 的非 PDF 图片
  -> 企业微信证据解析和发送只处理仍有 image_id 的非 PDF 图片
```

过滤应在引用数据离开聊天服务前集中完成，而不是只在企业微信适配器内处理。这样网页、分享页和所有聊天渠道都会执行同一策略，且企业微信在只有 PDF 图片候选时可以直接跳过后续证据图片解析。

## 文件识别规则

- 优先读取格式化前的 `docnm_kwd`，兼容读取格式化后的 `document_name`。
- 去除文件名首尾空白后进行不区分大小写的 `.pdf` 后缀判断。
- 文件名缺失或无法判断时不按 PDF 处理，避免误删非 PDF 问答配图；同时记录可诊断日志。
- 不使用 `doc_type`、图片 ID 命名或知识库名称猜测来源格式。

## 错误处理与兼容性

- 过滤只修改回答副本中的图片标识，不修改检索结果、索引数据或对象存储文件。
- 引用 Chunk、文字引用和来源文档链接必须继续保留。
- 非 PDF 图片发送失败时沿用现有隔离逻辑，不影响文字回答。
- 旧配置缺少新字段时按 `false` 处理。
- 已保存的历史引用在重新返回给客户端时应执行当前助手的过滤策略；数据库中的历史 JSON 不做破坏性重写。
- 已经通过外部渠道发送成功的历史图片不尝试撤回。

## 测试设计

后端单元测试覆盖：

- 开关关闭时清空 `.pdf`、`.PDF` 等 PDF Chunk 的图片标识。
- PDF Chunk 的文字、文档 ID、文档名称和引用顺序保持不变。
- 非 PDF 问答文档图片保持不变并可继续进入企业微信发送列表。
- PDF 与非 PDF 混合引用时只发送非 PDF 图片。
- 文件名缺失时不误删图片，并产生诊断日志。
- 开关开启时保持现有全部图片行为。
- 旧配置缺少字段时按关闭处理。

前端测试覆盖：

- 高级设置显示“展示 PDF 引用截图”开关。
- 新建助手和旧配置缺省时开关显示为关闭。
- 保存后字段正确写入 `prompt_config`。

## 验收标准

1. 开关关闭时，任何 PDF 来源的引用截图都不会出现在网页聊天、分享页面或企业微信新回复中。
2. 同一回答引用非 PDF 问答文档配图时，这些图片仍正常展示和发送。
3. PDF 的文字内容仍可用于回答，且文字引用和来源名称保持可见。
4. PDF 与非 PDF 混合引用时，只过滤 PDF 图片。
5. 无需重新解析知识库或执行数据库迁移。
