5. no-store 从 Minor 提升为 Important：首期明确要求不缓存员工资料，否则可能沿用已撤销的内容。
6. 旧启停审计从 Minor 提升为 Important：必须通过 user_id 记录操作者和时间，否则状态变更归属不完整。
7. 同名中心从 Minor 提升为 Important：错误选中中心可能把库授权给错误员工群体。
8. 未证实的 SSE 绑定风险通过首期仅允许 HTTP 排除；代价是员工模式拒绝 SSE，旧 Key 模式保留原能力。

10. 员工检索拒绝 TOC/KG 直接 API 扩展，父切片采用按库/文档验证及安全回退；代价是四工具以外的扩展需另行实现授权边界。
